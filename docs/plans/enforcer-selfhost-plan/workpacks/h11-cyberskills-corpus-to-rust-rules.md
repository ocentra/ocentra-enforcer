## Where We Are
The `anthropic-cybersecurity-skills` corpus (817 skills, Apache-2.0, by mukul975) is vendored at `vendor/anthropic-cybersecurity-skills/` for preservation, but nothing MECHANIZES it. Its detection knowledge lives only as Python `agent.py` scripts (~273/282 sampled shell out to an external CLI) plus prose `SKILL.md`/`references/*.md`. None of it is expressed as our Rust T1/T2 `Validator` rules, none of its MITRE/NIST frontmatter feeds `h03`'s threat vocabulary, and none of it is wired into the `enforcer-scan` (arc-15) router's security-audit scope (`f05`). The corpus is ALSO at risk of polluting our own dogfood: the enforcer's committed exempt-globs policy (read by `enforcer-config`, arc-03) does not yet list `vendor/**`, so the vendored Python would be scanned by the enforcer's own Rust rules as if it were our code — exactly the "dogfood must not drown in vendored Python" failure the owner named. The full disposition (Rust-convertible ~55-65% of skill cores vs python-bound ~15-20%, the T1/T2/T3/adapter breakdown, harvest targets, and the mapping plan) is documented in `vendor/anthropic-cybersecurity-skills/RUST_CONVERSION_ANALYSIS.md`.

## Where We Want To Be
The FUNDAMENTAL-LOGIC skills (regex tables, boolean field predicates, HCL/YAML/JSON manifest parsing, entropy scans, Rego deny-rules) are REIMPLEMENTED as native Rust `Validator`s — scaffolded through `d01` so each lands in 5-way parity (`RuleId` <-> doc-anchor <-> `Validator` <-> {fail+pass fixture} <-> `cargo test` detection test), with the threat-mapped rule record (CWE/OWASP/ATT&CK `ThreatId` newtypes) carried in `enforcer-rules` (arc-04). Placement per the crate map:
- The source-pattern / manifest / WAF-log detection rules land as `Validator` impls under `crates/enforcer-lang-security/src/rules/cyberskills/**` (the security source-pattern family crate, arc-10 — same home as d18's security-stop), parsing generic config/manifest/log input (`tree-sitter`/serde for HCL/YAML/JSON, regex tables for WAF logs), never a CLI subprocess.
- The frontmatter LINTER and the threat-VOCAB seed land in `crates/enforcer-security/src/cyberskills/{frontmatter_lint,vocab}.rs` (arc-19), because they feed `h03`'s canonical threat vocabulary in the Track H security crate.
The security-audit scope is wired through `f05`'s router (`enforcer-scan`, arc-15) so a detected repo routes to these packs and emits `Finding`s into the `g02` report with h03-validated threat citations. Each `Validator` returns `enforcer-domain::Finding` with a `Fix:` hint, obeys `[workspace.lints]` (no `unwrap/expect/panic/print_*`; no `pub use` barrels). The genuinely python-lib-bound skills (irreplaceable engines: symbolic execution, fuzzing, network scan, binary/memory forensics) are NOT reimplemented here — they are deferred to the optional adapter pack `h12` (out-of-dogfood). First pass is a THIN SLICE: the 7 highest-yield harvest targets + the frontmatter linter/vocab, not all 817 skills. GENERIC over the corpus; no single skill or engine is assumed present.

This pack does NOT redefine: the scaffolder/parity oracle (consumed from `d01`), the threat-vocabulary dictionary contract (consumed from `h03`; this pack SEEDS the dictionary h03 enforces), the crate skeletons (arc-10 / arc-19), or the detect/route plan shape (consumed from `f05`). It ports RULE CONTENT and drops the CLI dependency for the (a)/(b) cluster.

## Acceptance And Proof
Tier P1 (T1 blocking rules) / P2 (T2 scored matchers). Prove via `cargo test -p enforcer-lang-security` (source-pattern cluster) and `cargo test -p enforcer-security` (frontmatter lint + vocab). Per-rule fixtures under `crates/enforcer-lang-security/tests/fixtures/cyberskills/<ruleId>/{bad,good}/` (and `crates/enforcer-security/tests/fixtures/cyberskills/**` for the frontmatter/vocab half) with minimal-repro pairs (e.g. an S3 block with vs. without `server_side_encryption_configuration`; a storage account `enable_https_traffic_only==false` vs `true`; a response missing HSTS vs `max-age>=31536000`; a package.json with a public-resolvable private-looking name vs a scoped/secure one). The T2 `detect.waf.sqli-signature` fixture is a labeled corpus (benign vs malicious WAF log lines) asserted on confidence+severity, not single pass/fail.

Representative triples:
- terraform s3 encryption: fail `crates/enforcer-lang-security/tests/fixtures/cyberskills/iac.tf.s3-encryption-required/bad/no_sse.tf` (no SSE block -> flagged), pass `.../good/sse.tf` (SSE configured -> clean), `#[test] cyberskills_iac_tf`.
- azure require-https: fail `.../cloud.azure.storage-require-https/bad/http.json` (`enable_https_traffic_only:false`), pass `.../good/https.json` (`true`), `#[test] cyberskills_cloud_azure`.
- waf sqli score (T2): fail `.../detect.waf.sqli-signature/bad/union_select.log` (UNION SELECT line -> critical hit), pass `.../good/benign.log` (benign query -> below threshold), `#[test] cyberskills_waf_sqli`.
- dogfood exclusion: `#[test] cyberskills_vendor_not_dogfooded` asserts an `enforcer-scan` self-host scan of `vendor/**` returns zero findings (vendored Python ignored); a regression that scans it fails the test.
- frontmatter lint: fail `crates/enforcer-security/tests/fixtures/cyberskills/skill_frontmatter/bad/bad_attack_id.md` (malformed `T99` / unknown id -> flagged), pass `.../good/valid.md`, `#[test] cyberskills_frontmatter_lint`.

Detection tests iterate every fixture pair through the `Validator` (fail-flagged / pass-clean or scored) and run the d01 parity oracle over the family. Named proof rows in TEST_PROOF_EXPECTATIONS.md: `cyberskills-rule-detection`, `cyberskills-frontmatter-and-vocab`, and `cyberskills-vendor-dogfood-exclusion`. Record detection-test artifact paths there.
