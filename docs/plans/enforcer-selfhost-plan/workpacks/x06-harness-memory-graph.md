## Where We Are
x05 captures each lesson as a STRUCTURED RECORD and routes it into a landed harness surface (doctrine block / skill / rule-candidate / forest node) via a fail-closed doctor. But capture is only half of "memory": the landed corpus is WRITE-mostly. There is no RETRIEVAL — an agent starting a session on repo/task X cannot ask "what have we already learned that bears on this?" and get the top-k relevant lessons; nothing relates a lesson to the rules/workpacks/incidents it derived from or ships via; and nothing lets one machine's hard-won lesson reach another safely. The owner requirement (2026-07-04): as the harness gets used, captured lessons must become a RETRIEVABLE, SHAREABLE, FEDERATED memory — "like the memory graph system" (codebase-memory) but for harness/orchestration knowledge — so the whole enforcement system gets smarter with use, without a single lesson ever silently escaping the machine or silently activating on trust.

## Where We Want To Be
A new `crates/enforcer-memory` crate (an arc-26-class leaf) that turns the x05 corpus into a LOCAL-FIRST knowledge graph + vector index, exposed as MCP recall tools and a SessionStart recall injection. New crate rather than a module in `enforcer-plan`: memory has its own storage engine, its own optional embedding-runtime dependency, and its own sharing/federation surface — folding that mass into `enforcer-plan` (a scaffolder/validator crate) would blur two concerns and drag the embedder dep into every plan build. This adds ONE crate; crate-map delta is **28 -> 29** (net +1, `enforcer-memory`) — the primary wires this into RUST_ARCHITECTURE's crate map.

The graph nodes are `lesson | rule | workpack | harnessCapability | incident`; typed edges are `derivedFrom | shipsVia | supersedes | observedIn`. A vector index over lesson/doctrine text sits beside it. Both live under the install ledger root (`.enforce/memory/`, same append-only + verify-on-open discipline as `enforcer-proof`), ship inside the `enforcer` binary, and are queried via MCP tools (`memory search|recall|related`) plus a SessionStart recall that injects top-k lessons relevant to the current repo/task context through the c05 hook seam (cross-ref, not a dep). Retrieval is a small CPU embedder + optional reranker (Qwen3-Embedding-0.6B class, Apache-2.0, ONNX, Rust-native runtime), the model resolved as a downloadable artifact through the SAME resolver arc-23 uses for the binary — NO cloud calls; if the model artifact is absent, retrieval degrades to BM25/keyword and the degradation is LABELED (c02 capability doctrine), never silent. Sharing has three explicit-consent, default-CLOSED tiers: `personal` (default, never leaves the machine) / `team` (export/import signed lesson bundles via git or the coordination hub) / `community` (opt-in, anonymized + redacted through the enforcer-proof two-layer redaction before export). Federation is ZERO-TRUST: an imported lesson is UNTRUSTED prose until it routes through the x05 pipeline (rule-candidate with fixtures where applicable, doctrine block, forest node) and passes the x05 fail-closed doctor; provenance (source, signature, import date) is recorded on the node. A poisoned lesson is inert BY CONSTRUCTION — retrieval can SURFACE it, only local validation can ACTIVATE it.

## Requirement Checklist
- [ ] `src/graph.rs`: typed node model `MemoryNode { id: MemoryNodeId, kind: NodeKind, .. }` with `NodeKind = { Lesson, Rule, Workpack, HarnessCapability, Incident }` and typed edges `MemoryEdge { from: MemoryNodeId, to: MemoryNodeId, kind: EdgeKind }` with `EdgeKind = { DerivedFrom, ShipsVia, Supersedes, ObservedIn }`. serde camelCase; `MemoryNodeId`/`EdgeKind`-carried ids are branded `enforcer-domain` (arc-02) newtypes, parse-at-boundary, no bare `String` ids. Lesson nodes reference x05 `LessonId` (x05 records are the corpus).
- [ ] Storage under the install ledger root `.enforce/memory/` — append-only NDJSON graph log + vector index sidecar, verify-on-open (same discipline as `enforcer-proof`); never rewrite prior rows; supersede is an append. Graph + index ship inside the `enforcer` binary (no external service).
- [ ] `src/embed.rs`: retrieval stack behind a `Embedder` trait — small local CPU embedder (Qwen3-Embedding-0.6B class, Apache-2.0, ONNX, Rust-native runtime) + optional reranker. The model is a DOWNLOADABLE ARTIFACT resolved through the arc-23 artifact/download resolver (same path as binary distribution); NO cloud calls. Model-ABSENT is a LABELED capability degradation to BM25/keyword (c02 doctrine) — a `CapabilityState { embedder: Present|Degraded }` surfaced in results, never silent.
- [ ] `src/recall.rs` + MCP tool seam (arc-21): `memory search <query>` (vector/BM25 over lesson+doctrine text), `memory recall <repo/task context>` (top-k relevant lessons), `memory related <nodeId>` (graph-walk over typed edges). SessionStart recall injection is emitted through the c05 hook seam (cross-ref, NOT a dep): top-k lessons for the current repo/task context.
- [ ] `src/share.rs`: three sharing tiers, explicit consent per tier, default `personal` (never leaves machine). `team` = export/import SIGNED lesson bundles via git or the coordination hub. `community` = opt-in export anonymized + redacted through the `enforcer-proof` two-layer redaction. Default CLOSED: no tier is active without recorded consent.
- [ ] `src/federation.rs`: ZERO-TRUST import. An imported (team/community) lesson is UNTRUSTED prose — it MUST route through the x05 pipeline (rule-candidate + fail/pass fixtures where applicable, doctrine block, forest node) and pass the x05 fail-closed doctor before it can influence retrieval activation. Provenance (`source`, `signature`, `importDate`) is recorded on the node; an unsigned or tampered bundle is REJECTED at import. Retrieval MAY surface an unvalidated node (flagged `provenance=untrusted`); only local x05 validation flips it to active.
- [ ] Obey `[workspace.lints]` (no `unwrap`/`expect`/`panic`/`print_*`); no `pub use` barrels; deps `enforcer-domain` (arc-02 branded ids), x05 lesson records, arc-23 artifact resolver; c05 recall injection is a SEAM cross-ref, not a dep.

## Acceptance And Proof
Tier P1 (`harness-memory-graph` in TEST_PROOF_EXPECTATIONS.md) + P3 (`memory-recall-live` in TEST_PROOF_EXPECTATIONS.md), proved by `cargo test -p enforcer-memory` and a live MCP row:
- **Graph upsert/query (P1 pass):** upsert lesson/rule/workpack nodes + `derivedFrom`/`shipsVia` edges → `related` graph-walk returns the connected set; `search` over seeded lesson text returns the expected node.
- **Embedder-absent degradation (P1):** with no model artifact present, `search`/`recall` still return results via BM25 and the result carries a LABELED `CapabilityState::Degraded` — asserted present, never silent.
- **Federation reject (P1 fail):** importing an UNSIGNED or TAMPERED lesson bundle → REJECTED with a provenance/signature error; importing a valid-but-unvalidated bundle → node stored with `provenance=untrusted` and INERT (surfaced by retrieval, NOT active) until it passes the x05 doctor.
- **Redaction golden (P4):** `community`-tier export of a seeded lesson → byte-compared against a pinned golden under `tests/fixtures/memory/golden/**`, proving two-layer redaction (no machine/user/path leakage).
- **Live recall (P3):** the `memory recall` MCP tool, over a seeded corpus (the refs/orchestration-lessons.md L1..L11 imported via x05), returns topically-relevant lessons for a given repo/task context — a P3 live row, not a unit stub.
- Clean `cargo clippy` / `cargo fmt --check`.
