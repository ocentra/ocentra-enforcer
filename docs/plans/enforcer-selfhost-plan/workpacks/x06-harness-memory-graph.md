## Where We Are

x05 captures each lesson as a STRUCTURED RECORD and routes it into a landed harness surface (doctrine block / skill / rule-candidate / forest node) via a fail-closed doctor. But capture is only half of "memory": the landed corpus is WRITE-mostly. There is no RETRIEVAL — an agent starting a session on repo/task X cannot ask "what have we already learned that bears on this?" and get the top-k relevant lessons; nothing relates a lesson to the rules/workpacks/incidents it derived from or ships via; and nothing lets one machine's hard-won lesson reach another safely. The owner requirement (2026-07-04): as the harness gets used, captured lessons must become a RETRIEVABLE, SHAREABLE, FEDERATED memory — "like the memory graph system" (codebase-memory) but for harness/orchestration knowledge — so the whole enforcement system gets smarter with use, without a single lesson ever silently escaping the machine or silently activating on trust.

## Where We Want To Be

A new `crates/enforcer-memory` crate (an arc-26-class leaf) that turns the x05 corpus into a LOCAL-FIRST knowledge graph + retrieval system, exposed as MCP recall tools and a SessionStart recall injection. This is not "add a vector database". Per [MEMORY_RETRIEVAL_ARCHITECTURE](../MEMORY_RETRIEVAL_ARCHITECTURE.md), the source of truth is append-only lessons/observations/proof/artifact records; the graph, BM25, vector index, and reranker are derived query surfaces. New crate rather than a module in `enforcer-plan`: memory has its own storage engine, optional embedding runtime, artifact retrieval surface, evaluation harness, and sharing/federation surface — folding that mass into `enforcer-plan` would blur two concerns and drag retrieval/model deps into every plan build. This adds ONE crate; crate-map delta is **28 -> 29** (net +1, `enforcer-memory`) — the primary wires this into RUST_ARCHITECTURE's crate map.

The graph nodes are `lesson | rule | workpack | harnessCapability | incident | artifact | repoContext | modelArtifact | evalQuery`; typed edges are `derivedFrom | shipsVia | supersedes | observedIn | backedByArtifact | appliesToRule | appliesToWorkpack | activatedByX05 | importedFrom | redactedInto`. A sparse BM25/full-text index and a dense vector index over lesson/doctrine/artifact text sit beside it; artifact retrieval is a deterministic content-addressed subsystem, not vector search. All live under the install ledger root (`.enforce/memory/`, same append-only + verify-on-open discipline as `enforcer-proof`) and ship inside the `enforcer` binary by default. External vector DBs are adapter-only, never required for default operation.

Retrieval is local-first and hybrid: graph/table lookup for structured questions, exact artifact lookup for artifact refs, BM25 fallback always, optional local embedding + optional local reranker for fuzzy recall. First model seam: Qwen3-Embedding-0.6B class + Qwen3-Reranker-0.6B class through a Rag-Guide-compatible local model adapter (`/embed`, `/rerank`, `/health`), then ONNX/OpenVINO backends behind traits. OcentraParent's local-AI runtime concepts (capability flags, CPU/GPU/NPU resource class, model cache/load/degraded state, single local runtime lane) are adapted as DTO/state patterns, not a forced product dependency. If a model artifact is absent, retrieval degrades to BM25/keyword and the degradation is LABELED, never silent.

Sharing has three explicit-consent, default-CLOSED tiers: `personal` (default, never leaves the machine) / `team` (export/import signed lesson bundles via git or the coordination hub) / `community` (opt-in, anonymized + redacted through the enforcer-proof two-layer redaction before export). Federation is ZERO-TRUST: an imported lesson is UNTRUSTED prose until it routes through the x05 pipeline (rule-candidate with fixtures where applicable, doctrine block, forest node) and passes the x05 fail-closed doctor; provenance (source, signature, import date) is recorded on the node. Retrieval may surface an unvalidated lesson with warning; only local x05 validation can activate it.

- [ ] Storage under the install ledger root `.enforce/memory/` — append-only NDJSON graph log + materialized graph/read-model tables + BM25 index + vector sidecar, verify-on-open (same discipline as `enforcer-proof`); never rewrite prior rows; supersede is an append. Graph + default indexes ship inside the `enforcer` binary (no external service). DuckDB is optional analytics materialization for evidence curves, not source-of-truth.
- [ ] `src/index.rs`: backend traits for `MemoryLogStore`, `MemoryGraphStore`, `ArtifactStore`, `SparseIndex`, `VectorIndex`, and `RetrievalRuntime`. Default path = embedded store (SQLite/Tantivy/BM25 + embedded HNSW or equivalent vector sidecar); Qdrant/pgvector/LanceDB are optional adapters only after trait stability.
- [ ] `src/embed.rs`: retrieval stack behind `Embedder` + `Reranker` traits — small local CPU embedder (Qwen3-Embedding-0.6B class, Apache-2.0, ONNX/Rust-native runtime) + optional reranker (Qwen3-Reranker-0.6B class). Provide a Rag-Guide-compatible localhost adapter for dev smoke (`/embed`, `/rerank`, `/health`), then ONNX/OpenVINO feature backend. The model is a DOWNLOADABLE ARTIFACT resolved through the arc-23 artifact/download resolver (same path as binary distribution); NO cloud calls. Model-ABSENT is a LABELED capability degradation to BM25/keyword (c02 doctrine) — a `CapabilityState { embedder: Present|Degraded|Unavailable|Invalid, reranker: ... }` surfaced in results, never silent.
- [ ] `src/recall.rs` + MCP tool seam (arc-21): `memory search <query>` (hybrid graph/BM25/vector over lesson+doctrine+artifact summaries), `memory recall <repo/task context>` (top-k relevant lessons), `memory related <nodeId>` (graph-walk over typed edges), `memory artifact get <artifactId>` (exact artifact retrieval), `memory ingest`, `memory rebuild`, and `memory doctor`. SessionStart recall injection is emitted through the c05 hook seam (cross-ref, NOT a dep): top-k lessons for the current repo/task context, capped to a small configurable budget.
- [ ] **Learning-evidence query (the falsifiable-learning instrument — RUST_ARCHITECTURE "The learning thesis"):** `memory evidence <lessonId>` returns the t0→t1→t2 chain as a typed record: t0 = the `observedIn` incident node(s) with provenance; t1 = the landed artifact refs (x05 `landedAt`, fixtures green); t2 = recurrence count of the fault class SINCE landing (graph query over post-t1 incidents), each element carrying `enforcer-proof` journal refs (tamper-evident). An aggregate `memory evidence --all` emits the learning curve (per-domain `harness|code` violation/recurrence rates over time) — the benchmark proving experience-driven learning. Fail-closed: a lesson with no t0 provenance reports `evidence: incomplete`, never fabricates a chain.
- [ ] `src/share.rs`: three sharing tiers, explicit consent per tier, default `personal` (never leaves machine). `team` = export/import SIGNED lesson bundles via git or the coordination hub. `community` = opt-in export anonymized + redacted through the `enforcer-proof` two-layer redaction. Default CLOSED: no tier is active without recorded consent. Bundle format includes manifest, checksums, signature, lessons, observations, artifact manifest, and redacted blobs.
- [ ] `src/federation.rs`: ZERO-TRUST import. An imported (team/community) lesson is UNTRUSTED prose — it MUST route through the x05 pipeline (rule-candidate + fail/pass fixtures where applicable, doctrine block, forest node) and pass the x05 fail-closed doctor before it can influence active recall. Provenance (`source`, `signature`, `importDate`) is recorded on the node; an unsigned or tampered bundle is REJECTED at import. Retrieval MAY surface an unvalidated node (flagged `provenance=untrusted`); only local x05 validation flips it to active.
- [ ] **Usage-ingestion seam (owner-set: "as I ask to investigate code — more learning; scan a repo — more learning"):** every enforcement operation FEEDS the graph automatically — `src/graph.rs` exposes an `ingest_observation` function contract (finding/fault-class/ruleId/repo-context → `Incident` node + `observedIn` edges) that the scan/check/run surfaces (arc-15, f01, f05 router) and the coordination closeout (arc-16) CALL on every run; no manual capture step. Ingestion is append-only, redaction-safe at write, and is what populates t0 for the learning-evidence chain — a scan that finds nothing still records the clean observation (negative evidence moves the learning curve too). Seam = function contract consumed by those crates' own packs, not shared files.

- [ ] Retrieval trace + diagnostics: every memory query records a local redacted trace (route, filters, candidate counts, score families, selected ids, capability state, index manifest id, latency) and resource diagnostics NDJSON; no raw private source text or prompt text in traces.

## Acceptance And Proof

Tier P1 (`harness-memory-graph` in TEST_PROOF_EXPECTATIONS.md) + P3 (`memory-recall-live` in TEST_PROOF_EXPECTATIONS.md), proved by `cargo test -p enforcer-memory` and a live MCP row:
- **Graph upsert/query (P1 pass):** upsert lesson/rule/workpack/artifact/repo/model/eval nodes + `derivedFrom`/`shipsVia`/`backedByArtifact` edges → `related` graph-walk returns the connected set; `search` over seeded lesson text returns the expected node.
- **Artifact exactness (P1 pass/fail):** `memory artifact get <artifactId>` returns the exact artifact by id/hash; a query for a different-but-similar artifact does not return a false exact match.
- **Embedder-absent degradation (P1):** with no model artifact present, `search`/`recall` still return results via BM25 and the result carries a LABELED `CapabilityState::Degraded` — asserted present, never silent.
- **Hybrid eval (P1):** seeded memory queries report `hit@k` / `recall@k` / `MRR` / `nDCG`; expected lesson ids are retrieved; unauthorized/untrusted candidates are zero before rerank/context assembly.
- **Federation reject (P1 fail):** importing an UNSIGNED or TAMPERED lesson bundle → REJECTED with a provenance/signature error; importing a valid-but-unvalidated bundle → node stored with `provenance=untrusted` and INERT (surfaced by retrieval, NOT active) until it passes the x05 doctor.
- **Redaction golden (P4):** `community`-tier export of a seeded lesson → byte-compared against a pinned golden under `tests/fixtures/memory/golden/**`, proving two-layer redaction (no machine/user/path leakage).
- **Live recall (P3):** the `memory recall` MCP tool, over a seeded corpus (the refs/orchestration-lessons.md L1..L11 imported via x05), returns topically-relevant lessons for a given repo/task context — a P3 live row, not a unit stub.
- Clean `cargo clippy` / `cargo fmt --check`.
