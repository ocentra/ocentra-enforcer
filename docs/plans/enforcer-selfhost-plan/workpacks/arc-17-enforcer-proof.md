## Where We Are
The proof harness — routed proofs, artifact capture, freshness, PR-ready claims, legacy import — lives across `src/proof-*.mjs` / `scripts/profile-proof-runner.mjs` as ad hoc JS. It is not a workspace crate.

## Where We Want To Be
`enforcer-proof` is the Rust proof harness per RUST_ARCHITECTURE.md: it runs routed proofs, captures artifacts, tracks freshness, and emits PR-ready claims, built on `enforcer-domain` (`Sha256` artifact hashes, `Report`) and driven by the scan engine. Per the OcentraParent audit/proof tamper-evidence borrow it adds an **append-only SHA-256 hash-chained NDJSON journal** (`src/journal.rs`): each record's hash folds in the previous record's hash, so the log is tamper-evident. The journal is **verified-on-open AND on-replay** (any break in the chain fails closed). It CONSUMES `enforcer-core`'s generic append-only `NdjsonWriter<T>` sink + the pure hash-chain primitive (no duplicated crypto here), and KEEPS the existing rich proof envelope (`src/envelope.rs`: git-state / in-toto / retention). Journal records are versioned serde structs (`schema_version` + `eventType`) reusing `enforcer-domain` newtypes, with two-layer redaction applied by `enforcer-core`.

### Decomposed provable rows (each names a concrete mechanic from `src/proof.mjs` / `src/proof-storage.mjs` / `src/proof-legacy.mjs`; each ships a fail fixture and a pass fixture)

- [ ] **[G7] in-toto attestation.** Every run writes `attestation.json` (`writeProofFiles` -> `attestationFor`): an in-toto **Statement v1** (`_type: "https://in-toto.io/Statement/v1"`), `predicateType: "https://ocentra.dev/attestations/proof-run/v1"`, `subject[0].name = proofId`, and `subject[0].digest = { gitCommit }`. **Preserve the non-standard `gitCommit` digest key intentionally** (in-toto expects `sha256`/`sha512`; ours is deliberately `gitCommit` so the subject binds to the proved commit, not a file). `predicate` carries `runId`/`status`/`startedAt`/`endedAt`/`capability`. Fixture: PASS = emitted attestation round-trips to the exact shape incl. `gitCommit` key + commit value; FAIL = a serializer that renamed the key to `sha256` (or dropped the subject) is rejected by the golden-shape assertion.
- [ ] **[G8] git-provenance claim gates.** `claimProof` gates a PR-ready claim against `gitState(root)` and emits typed violations (`{proofId, code, message, severity:"error"}`): `missing-proof-run` (no run for id), `proof-not-passed` (`run.status !== "passed"`), `stale-commit` (`currentGit.commit !== run.git.commit`), `dirty-worktree` (`args.prReady && currentGit.dirty && !args.allowDirty`), `missing-artifact` (a `run.artifacts[].path` no longer exists on disk), `deleted-required-path` (a `definition.requiredPaths[]` no longer exists). Claim `ok` iff `violations.length === 0`; default proof set = all `requiredForPrReady` proofs. Preserve the **`--allow-dirty` / `allowDirty` escape hatch** (suppresses only `dirty-worktree`). Fixtures: PASS = fresh+clean+present -> `ok:true`, empty violations; FAIL rows = one fixture per gate (stale commit, dirty worktree without allowDirty, deleted artifact, deleted required path, not-passed, missing run) each asserts that exact `code`; plus PASS = dirty worktree **with** `allowDirty` -> no `dirty-worktree` violation.
- [ ] **[G9] THREE distinct legacy ops (the point of migration is deletion-readiness).** (a) **`migrateLegacyProofs`**: classify `scripts/test/**.mjs`, generate a per-profile `profiles/<profile>/proofs.json` (via `legacyScriptProofDefinition`) AND copy each source script into `profiles/<profile>/legacy-scripts/<origPath>`; honor `dryRun` (default; no writes) vs `write`. (b) **`importLegacyProof`**: collect legacy artifacts (`test-results`/`output`/`docs/proof`), **SHA-256 hash** each, write them under `runs/<id>/artifacts/legacy/**` + a `legacy-manifest.json`, and produce a real proof run with an **in-toto** envelope (status `passed` iff artifacts found AND no failed artifacts). (c) **`proofParity`**: compare collected legacy hashes+claims against the imported run and classify coverage as **`equivalent` | `weaker` | `not-comparable`**, computing **`deletionReady`** (= `equivalent && run.status==="passed" && no failed artifacts`) — the gate that says the old script batch may be deleted. Fixtures per op: migrate dry-run writes nothing / migrate write emits registry+copies (PASS) vs missing scripts dir (FAIL/empty); import round-trip hashes match manifest (PASS) vs zero-artifact -> status `failed` (FAIL); parity equivalent+passed -> `deletionReady:true` (PASS) vs hash mismatch/missing run -> `weaker`/`not-comparable`, `deletionReady:false` (FAIL).
- [ ] **[G10] `proofs.json` registry schema + merge + routing.** Model the proof-definition record: `id`/`title`/`family`/`severity`/`appliesTo`/`triggers`/`languages`/`capabilities`/`collector`/`docs`/`commands`/`requiredArtifacts`/`requiredPaths`/`requiredForPrReady`/`claimsProved`/`claimsNotProved`/`ciSupport`/`deviceSupport`. `loadProofRegistry` reads base `proof/proofs.json` and, when a profile is named, **deep-merges** `profiles/<profile>/proofs.json` over it by `id` (`mergeProofDefinitions`: profile entry replaces same-id base entry; `schemaVersion = max`). `routeProofs` selects definitions by explicit `proofId` OR by `proofFamilyKeys` matching (`proofMatchesRoute`: capability must be in `capabilities`; plan must match `appliesTo`+`triggers`; `scope:workspace` -> `appliesTo` has `workspace` or `family==="claim-integrity"`; else any family/language/capability/trigger/appliesTo key hit). Fixtures: PASS = profile override wins over same-id base entry; PASS = a `.rs` file routes to rust-triggered proofs, a workspace scope routes to the claim-integrity proof; FAIL = capability filter excludes a non-matching proof (empty result asserted).
- [ ] **[G11] manual-required / unavailable states + capability model + PROOF-MANUAL diagnostic.** When `runProof` gets an empty command it calls `writeManualProofRun` with status **`manual-required`** (when `capability === "manual-required"` or `collector === "manual-artifact"`) else **`unavailable`**, emits a single diagnostic with `ruleId: "PROOF-MANUAL"` (severity `warning` for manual-required, `error` for unavailable), and returns `ok:false`. Capability is resolved as `args.capability ?? definition.capabilities[0] ?? "local"`; the capability vocabulary (`local`/`ci`/`windows`/`linux`/`macos`/`wsl`/`android-*`/`ios-*`/`browser`/`network`/`cloud`/`manual-required`) is inferred by `scriptCapabilities`. `proofLastFailure` treats `failed`/`manual-required`/`unavailable` as failures. Fixtures: FAIL = no-command manual-artifact proof -> status `manual-required` + `PROOF-MANUAL` warning + `ok:false`; FAIL = no-command non-manual proof -> `unavailable` + `PROOF-MANUAL` error; PASS = real command proof -> `passed`, no PROOF-MANUAL row.
- [ ] **[G6] retention constant-vs-config divergence.** Port `DEFAULT_PROOF_RETENTION` (`maxRunsPerProof:20`, `maxFailedRuns:20`, `maxArtifactBytes:50MiB`, `pruneAfterDays:14`, `pinPrReadyDays:30`) as the retention policy `pruneProofRuns` enforces (keep pinned; keep newest `maxRunsPerProof` per proofId; keep newest `maxFailedRuns` non-passed; drop runs older than `pruneAfterDays`; then rewrite the manifest). Decision to bake in: either wire pin-age into pruning (a pinned run past `pinPrReadyDays` becomes prunable) or delete the dead field — do NOT silently carry a no-op knob. Fixtures: PASS = >20 runs for one proofId prunes to 20 keeping newest + all pinned; PASS = a run older than `pruneAfterDays` is removed unless pinned; FAIL = the dead `pinPrReadyDays` has an explicit test asserting the resolved behavior (either enforced or absent), so it cannot regress into a silent no-op.
