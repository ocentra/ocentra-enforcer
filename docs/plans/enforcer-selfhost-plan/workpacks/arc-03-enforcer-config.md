## Where We Are
Config and env handling is scattered across `.mjs` (ad hoc `process.env` reads, JSON parsing without validation, per-script option parsing). There is no typed, parse-at-boundary config layer, so invalid config surfaces as runtime failures deep in the engine. HOWEVER a real, already-working THREE-LAYER config model exists today and must be PRESERVED, not flattened: (1) global/shared **profiles** — `profiles/{strict,ocentra-enforcer,ocentra-parent}.json`, each a COMPLETE config shape, the "any project, zero config" fallback; (2) the **per-project config** (`ocentra-enforcer.config.json`) which declares `profileName` (which global profile it layers on top of) + local overrides — self-mechanically-enforced today by `CFG-1.10`/`CFG-1.11` (must declare `schemaVersion`+`profileName`; `profileName` must be one of `knownProfiles = {strict, default, ocentra-enforcer, ocentra-parent}`); (3) **per-run OUTPUT** under `.enforce/runs/<id>/**` (diagnostics/verdicts) — this is NOT config, it is the harness's job (arc-18/arc-17), config only resolves the settings (incl. the `harness` sub-object: storageDir/maxRuns/retention) those crates consume.

## Where We Want To Be
`enforcer-config` provides typed config loading with parse-at-boundary AND preserves the 3-layer resolution: EMBED the canonical profiles into the binary at compile time (`include_str!` or a build-script, so the engine is self-contained per the "one binary IS the engine" doctrine — no external `profiles/` dir required for baseline operation, though a project may still supply extra custom profiles as external files); load the project's `ocentra-enforcer.config.json` (or its `.enforce/config` successor per f03) if present; resolve `profileName` -> the matching embedded (or custom) profile as the DEFAULTS layer; deep-merge the project's local overrides on top to produce ONE typed, total `EffectiveConfig` struct built on `enforcer-domain` newtypes. If no project config exists at all, the "default" profile alone IS the effective config — zero-config projects work out of the box. Downstream crates (scan/harness/proof/lang-*) consume only the resolved `EffectiveConfig`, never raw files/env.

## Requirement Checklist
- [ ] Implement typed config load per RUST_ARCHITECTURE.md (`enforcer-config`): parse config file(s) + env into validated structs built on `enforcer-domain` newtypes.
- [ ] Embed the canonical profiles (`strict`, `ocentra-enforcer`, `ocentra-parent`, `default`) into the binary at compile time; support additional custom profiles supplied as external files by a project.
- [ ] Implement 3-layer resolution: profile (defaults) -> project config (local overrides, deep-merged) -> `EffectiveConfig` (total, no downstream `Option` soup for required fields). Zero project config => the `default` profile alone is the effective config.
- [ ] Preserve the mechanical self-check semantics of `CFG-1.10`/`CFG-1.11` as TYPED LOAD ERRORS (not runtime findings): a project config missing `schemaVersion` or `profileName` fails to load with a typed error; a `profileName` that isn't in the known-profiles set fails to load with a typed error naming the unknown value.
- [ ] Parse-at-boundary: all validation happens at load; the returned config is total, with clear typed errors on malformed input.
- [ ] Port the `.mjs` env/JSON/option-parsing conventions (the config-shaped reads currently in `scripts/*.mjs` and `mcp/*.mjs`) into this crate.
- [ ] Add a `supportedPlatforms: ["windows"|"macos"|"linux", ...]` field to the config/profile shape (defaults to all three if absent — no silent relaxation by omission); this is what `PORT-1.1` in `enforcer-lang-common` (arc-09) reads to scope its platform-specific-script check to the project's DECLARED CI platforms rather than blanket-failing.
- [ ] **EffectiveConfig field-set round-trip [G5].** The `EffectiveConfig` struct must model AND round-trip (profile-defaults deep-merged with project overrides, then re-serialized identically) the FULL real field set observed in `profiles/{strict,ocentra-parent}.json` + `ocentra-enforcer.config.json`, not a generic "config-shaped reads" bucket. Enumerate as typed fields on `enforcer-domain` newtypes, grouped, each group with its OWN fail/pass fixture (a profile JSON slice + the parsed struct it must produce; and a round-trip assert `parse(serialize(x)) == x`):
  - *Shape-ownership globs (6, `Vec<Glob>`):* `rawTypeBoundaryGlobs`, `facadeFileGlobs`, `rawStringOwnerGlobs`, `domainPrimitiveOwnerGlobs`, `serializedDomainOwnerGlobs`, `runtimeStringOwnerGlobs`. Fixture: `ocentra-parent` non-empty owner globs vs `strict` empty-list defaults.
  - *Runtime-literal policy (4):* `enforceRuntimeStringLiterals: bool`, `runtimeStringLineAllowPatterns: Vec<Regex-source>` (must preserve the 9 escaped-regex allow patterns verbatim — round-trip MUST NOT mangle `env!\\(`, `#\\[serde`, the `const … &str` pattern, etc.), `enforceSerializedPublicDomainPrimitives: bool`, `enforceWorkspaceFiles: bool`. Fixture: `ocentra-parent` (enforce=true) vs `strict` (enforce=false).
  - *Cargo / dependency policy (11):* `blockedProtocolDependencies: Map<CrateName, Vec<CrateName>>` (the ONLY map field — `ocentra-parent` maps `ocentra-parent-agent-protocol` -> 5 forbidden crates; `strict`/`ocentra-enforcer` empty map; fixture must prove empty-map vs populated-map both round-trip), `runtimeCrates: Vec<CrateName>`, `testOnlyCrates: Vec<CrateName>`, `allowedGitDependencies: Vec<...>`, `allowGitDependencies: bool`, `allowPathDependencies: bool`, `allowBuildRs: bool`, `allowUnsafeCode: bool`, `publicReexportPolicy: enum {forbid|allow|…}` (both real profiles = `"forbid"`), `requireCargoDeny: bool`, `requireCargoAudit: bool`.
  - *Rust roots / scan scope (7):* `rustRoots: Vec<PathGlob>`, `crateRootGlobs: Vec<Glob>`, `testFileGlobs: Vec<Glob>`, `cargoOnFileScope: bool`, `cargoOnDiffScope: bool`, `cargoTestThreads: Option<NonZeroUsize>` (both profiles = `null` -> `None`; fixture must prove `null` -> `None` and a numeric value both round-trip), `runCargoDoc: bool`, plus `failFast: bool`. Fixture: `ocentra-parent` (`rustRoots` = tauri+crates+tools) vs `strict` (`src`+crates+tools).
  - Cover-all assert: a proof fixture that loads each of `strict.json`, `ocentra-parent.json`, `ocentra-enforcer.config.json` end-to-end and asserts EVERY key present in the JSON is consumed by a typed field (no silent `#[serde(flatten)]` drop, no `deny_unknown_fields` panic) — the mechanical guarantee that the field set is complete, not sampled.
- [ ] **`sourceShapePolicies` base shape has a home HERE [G4].** The per-root/per-ext shape budget is a FIRST-CLASS config field (currently unhomed in the plan; a08 must NOT own it — a08 owns only dishonest waivers). Model `sourceShapePolicies: Vec<SourceShapePolicy>` where each entry = `{ roots: Vec<PathGlob>, extensions: Vec<Ext>, kind: enum{typescript|rust|python|common}, maxClasses?, maxExports?, maxFunctions?, maxFunctionLines?, maxLines?, maxTypes?: usize }` (all limit fields `Option<usize>` — a policy sets only the dimensions relevant to its `kind`, e.g. the rust entry sets `maxTypes` not `maxClasses`). Fixture: the 3-entry `sourceShapePolicies` block from `ocentra-enforcer.config.json` (2 typescript roots + 1 rust root) round-trips; a policy omitting a limit yields `None` (unbounded), not `0`. Reference note: arc-04 (rules) consumes these resolved budgets to run the source-shape check; the HONEST per-file tuning + DISHONEST-bump distinction lives in a08 and references THIS shape.
- [ ] **`ocentra-parent` profile posture as a named resolution target.** The config layer must correctly resolve the `ocentra-parent` profile's specific hardened posture, and a proof fixture must assert the resolved `EffectiveConfig` reflects it: `publicReexportPolicy == forbid` (pub-use forbidden repo-wide), `enforceRuntimeStringLiterals == true` (runtime-literal ban) with the 6 `runtimeStringOwnerGlobs` populated, `enforceSerializedPublicDomainPrimitives == true` (domain-typed serialized fields) with `serializedDomainOwnerGlobs` populated, and `blockedProtocolDependencies` carrying the protocol-crate dep bans (`ocentra-parent-agent-protocol` may not depend on the 5 runtime crates). This is the concrete "hardened consumer profile" the config layer must resolve without loss — distinct from `strict` (same `forbid` posture but empty owner globs / literal-ban off) and the zero-config `default`.
- [ ] `cargo test -p enforcer-config` passes with fail/pass fixtures: valid config with a known profile loads and correctly merges overrides over profile defaults (pass); zero config falls back to the `default` profile alone (pass); missing `schemaVersion`/`profileName` fails typed (fail); unknown `profileName` fails typed, naming it (fail); env-override tests; `supportedPlatforms` present vs. absent-defaults-to-all-three.
- [ ] Clean `cargo clippy` / `cargo fmt --check`.
