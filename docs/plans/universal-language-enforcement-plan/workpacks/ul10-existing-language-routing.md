## Where We Are

Dart and CFML rule crates exist but are absent from the scan engine's validator families. Go is detected and structurally parsed but has no dedicated rule pack/tool route. Router comments and live crates disagree.

## Where We Want To Be

Each selected identity has an honest route: existing native validators and mature ecosystem tools run through shared contracts, or the capability row explicitly reports unsupported/unavailable behavior.

## Owns

- one language adapter/test directory and immutable route/capability proposal;
- no shared router, engine dispatch, language registry, tool registry, workspace manifest, or capability matrix edit by the child.

## Objective

Close known routing contradictions before scaling to additional languages.

## Requirement Checklist

- [ ] Audit current crate, parser facts, native tool candidates, rules, fixtures, and stale docs for the selected language.
- [ ] Reuse mature analyzer/linter/test tools through UL07 where justified.
- [ ] Route exact files and prove validator/tool selection, diagnostic language, ordering, and failure behavior.
- [ ] Missing executable/version/config is typed and policy-controlled, never zero findings/pass for a required tool.
- [ ] Capability row names L0-L5 levels and `notProved`.
- [ ] Child submits shared-file proposals only; integrator applies them serially.

## Acceptance And Proof

Focused language crate/tool fixtures, router/scan/MCP integration, invalid/unavailable cases, capability proposal validation, and Enforcer gates must pass on child and integrated SHAs.

## Stop conditions

Stop if the selected language needs a new grammar/fact, generic tool runner, domain contract, workspace dependency, or edits outside its exact packet.

## Parallel Ownership Notes

Dart, CFML, and Go audit/leaf packets may run in parallel on disjoint paths. Shared routing/capability changes are applied by one integrator after all accepted proposals are compared.
