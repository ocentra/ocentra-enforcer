# Worker Checklist

## Before editing

- [ ] One workpack instance and exact owns are named.
- [ ] Branch/worktree/base SHA and inherited residue are recorded.
- [ ] Enforcer route completed for exact files.
- [ ] Lane registered; start mail sent; claims accepted; guard green.
- [ ] Shared files are owned only by the named integrator.

## During work

- [ ] One capability slice only.
- [ ] Positive, negative, malformed, and unavailable-capability behavior covered.
- [ ] Parser/tool failure cannot become clean.
- [ ] Unknown identity, recognized-but-unsupported capability, and unavailable provider are emitted as distinct typed outcomes.
- [ ] An external tool route reuses the accepted UL07 `enforcer-harness` contract; no local process runner was added.
- [ ] No raw Tree-sitter type crosses the syntax boundary.
- [ ] No hard-coded framework verdict bypasses doctrine resolution.
- [ ] Inner compile/test and Enforcer file scan run after each cohesive edit.

## Before handoff

- [ ] Workpack proof row is green with run IDs.
- [ ] Diff contains only claimed paths and no protected residue.
- [ ] Guard is green for commit/push operation.
- [ ] Task branch commit pushed; exact SHA mailed.
- [ ] Claims released/closed and manager can reproduce the decisive gate.

## No-claim statement

Every handoff states which capability level was proved and what remains unsupported. It never says “language supported” without the level and evidence row.
