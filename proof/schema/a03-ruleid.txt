=== ruleId<->registry parity ===
crates/enforcer-rules/src/registry.rs already consumes enforcer_domain::ids::RuleId
exclusively: `RuleRecord.rule_id: RuleId`, `RuleRegistry { records: BTreeMap<RuleId,
RuleRecord> }`, and `RuleRegistry::get(&self, rule_id: &RuleId)` -- there is no path
by which a bare String reaches the registry's key/lookup API. This pack's added test
(ids::tests::rule_id_required_at_a_registry_shaped_boundary_not_bare_string) proves
the same shape (`BTreeMap<RuleId, _>` + a `&RuleId`-typed lookup helper) at the
enforcer-domain boundary, ahead of enforcer-rules depending on it.

=== compile-reject fixture (manual, proved at review time -- see acceptance
criterion "the private field enforces at compile time that a bare String cannot
substitute for RuleId") ===
The following does NOT compile against crates/enforcer-domain/src/ids.rs +
crates/enforcer-rules/src/registry.rs:

    fn bad_lookup(map: &std::collections::BTreeMap<enforcer_domain::ids::RuleId, &str>) {
        map.get("RR-6.1"); // expected `&RuleId`, found `&str`
    }

    fn bad_insert(map: &mut std::collections::BTreeMap<enforcer_domain::ids::RuleId, &str>) {
        map.insert("RR-6.1".to_owned(), "x"); // expected `RuleId`, found `String`
    }

Fails with E0308 (mismatched types) / a missing `Borrow<str>` impl path: RuleId(String)
has a private inner field and only a validating TryFrom<String>/FromStr constructor, so
no bare String or &str literal converts to RuleId implicitly, and BTreeMap::get's
Ord/Borrow-based lookup does not accept a different key type without that conversion.
