=== compile-reject fixture (manual, proved at review time -- see acceptance
criterion "private field + distinct types make RelPath substituting for
RepoRoot a compile error") ===
The following does NOT compile against crates/enforcer-domain/src/paths.rs:

    fn takes_root(_r: &enforcer_domain::paths::RepoRoot) {}
    fn bad(rel: enforcer_domain::paths::RelPath) {
        takes_root(&rel); // expected `&RepoRoot`, found `&RelPath`
    }

    fn bad_resolve(
        root: &enforcer_domain::paths::RepoRoot,
        other_root: &enforcer_domain::paths::RepoRoot,
    ) {
        root.resolve(other_root); // expected `&RelPath`, found `&RepoRoot`
    }

Both fail with E0308 (mismatched types): RepoRoot(String) and RelPath(String)
are distinct newtypes with private inner fields and no From/Into conversion
between them; RepoRoot::resolve's signature is
`fn resolve(&self, rel: &RelPath) -> String`, so there is no overload
accepting a second RepoRoot, and no method anywhere in the module accepts
two RelPaths as a base.
