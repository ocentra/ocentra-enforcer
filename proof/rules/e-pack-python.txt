=== HARDENING PASS (2026-07-11) — missing rule BEHAVIOR filled in ===
The 14 PYFA-* rules were already present and green; this pass closed
false-negative gaps where a rule claimed to detect a class of anti-pattern
but only matched one literal spelling, so realistic FastAPI code slipped
through. No new rule ids, records, fixtures-in-catalog, or doc anchors were
added (5-way parity unchanged); only Validator detection breadth and proof
fixtures were extended, all within pack-owned paths.
- PYFA-4.1 no-orm-models-in-services: was hardcoded to `from app.models`;
  now flags any import whose module path has a whole `models` segment
  (`from myproj.models`, `from ..models`, `from .models`, `import x.models`),
  while `data_models` / `app.domain.order_dto` stay clean.
- PYFA-10.1 no-sync-http: added the omitted verbs requests.patch/delete/head/
  options/request and urllib.request.urlopen alongside get/post/put and the
  sync httpx.Client.
- PYFA-12.2 insecure-random-token: added random.randrange/getrandbits/sample/
  uniform alongside choice/randint/random. (random.shuffle was deliberately
  NOT added: it returns None / shuffles in place -- a weak token-minting
  signal -- and the literal `random.shuffle(` contains the substring `.sh`,
  which self-collides with the enforcer's own PORT-1.1 Linux `.sh` script
  marker when it dogfoods this crate's source.)
- PYFA-12.3 cors-wildcard: now whitespace-normalized and #-comment-aware, so
  `allow_origins = [ "*" ]` is caught, not only the exact `allow_origins=["*"]`.

=== KNOWN BLOCKER (honest disclosure — NOT owned by this pack) ===
The 14 PYFA-* validators are reachable ONLY via their own cargo tests
(detection + parity) and the fastapi-layered.json catalog; they are NOT wired
into the runtime scan path. `enforcer-scan/src/engine.rs::build_family_validators`
collects `enforcer_lang_py::all_validators()` (the 61 rules.json-backed PY-*
validators), which by design (lib.rs:25-30) excludes rules::fastapi_layered.
This is the IDENTICAL posture of sibling families d16 (fsm.json /
enforcer_lang_common::rules::fsm) and d22 (size-shape.json /
size_shape) — none of the "NEW-mechanism" JSON-catalog families are dispatched
at runtime yet; the engine does not load JSON catalogs at all. Wiring these
families into the scan engine is a shared concern owned by the Validator
registration root (arc-08 crate skeleton) + the scan dispatcher (arc-14/f05),
which this workpack is explicitly forbidden from touching. Reported, not
fixed. No PYFA rule can block a real `enforcer scan`/`enforcer check` until
that shared wiring lands.
