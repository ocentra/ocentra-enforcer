Design note: unlike most line-scan validators in this workspace (see
`enforcer-lang-security`'s `text_scan` module doc), this validator is
deliberately NOT comment-guarded — the violation shape (`// eslint-disable`,
`# noqa`, `@ts-ignore`, ad-hoc `enforcer-disable`/`enforcer-ignore`/
`enforcer-bypass`, `clippy::allow` on the deny wall) IS itself a comment
or attribute, so skipping comment-only lines would defeat the entire
check.

Doctrine enforced: `enforcer-config` is the single declarative
control-plane; the ONLY legitimate exemption path is a declarative,
committed, gated waiver (owner+reason+ruleId) read from there — never an
inline comment. This validator does not itself read `enforcer-config`
(that wiring is the scan orchestrator's job, arc-14+); it unconditionally
bans the inline escape-hatch shape at the source-text level, in every
scanned file regardless of source language.
