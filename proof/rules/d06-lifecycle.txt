=== Acceptance-criteria mapping ===
- "Five subcommands registered ... with stable exit-code semantics": Phase enum
  (Plan/Implement/Check/Fix/Review) + one run_* fn per phase in src/lifecycle.rs,
  each folding its oracle's PhaseVerdict into ExitCodeShim (-> ExitCode). Clap
  wiring into crate::cli::Command/main.rs is arc-22's owned surface (see
  "Integration seam" module doc + Deviations below) -- the dispatch table and
  typed verdict->exit-code fold this criterion actually asks for are landed and
  proven here.
- "Each phase delegates its verdict to a named oracle": src/lifecycle/oracle.rs
  -- plan_oracle/implement_oracle/check_oracle/fix_oracle/review_oracle, one
  function per phase, dispatched from src/lifecycle.rs's run_* wrappers.
- "fix invokes the d07 fix loop; review requires green proof rows": fix_oracle
  fails closed (NotYetWired) -- d07 has not landed a fix-loop entry point on
  this branch (enforcer-coordination::api exposes hub/lane/claim/guard/ledger/
  sync only). review_oracle wires the LANDED half (enforcer-proof::claim's
  pr_ready claim gate, proven by review_oracle_passes_when_claim_is_clean /
  review_without_proof_rows_is_blocked) -- the d10 auditor-obligation evidence
  layer the workpack also names has not landed a Rust API on this branch
  either (no auditor crate/module exists) and is therefore NOT consulted.
- "No phase can report success unless its oracle returns a pass": proven by
  plan_implement_fix_phases_never_report_success_with_no_landed_oracle (fails
  closed on all three not-yet-wired phases) and
  check_phase_reports_violations_class_on_a_fail_fixture_tree (a phase reports
  success while its oracle returns fail -> that test fails, i.e. this
  invariant is what is actually asserted).
- "review blocks on missing proof rows": review_without_proof_rows_is_blocked.
- "Phase transitions recorded as d04 telemetry": record_transition() in
  src/lifecycle.rs appends an enforcer_domain::run_record::RunRecord through
  enforcer_core::telemetry::RunTelemetrySink at the default
  proof/telemetry/runs.ndjson path, exactly the sink/shape d04 defines --
  telemetry emission is an observer (best-effort; a sink open/append failure
  never flips a phase's own exit code), matching enforcer-core::telemetry's
  documented contract.
